# Spline sketch

## ChatGPT summary

- dokáže odpovídat na rank queries v čase $\boh(\frac{n}{k} \log \alpha)$
  -  $n$ je pocet prvku, ktere jsme videli
  -  $k$ je pocet kyblicku, ktere mame
  -  $\alpha$ je nejaky koeficient (aspect ratio)

- kazdy bucket v sobe drzi, kolik do nej priblizne spada prvku $b_i$
  - rank pote spocitame jako prefixovy soucet z hodnot v bucketech + PCHIP interpolace

- PCHIP (Piecewise Cubic Hermite Interpolating Polynomial)
  - stara se predevsim o to, aby byla dobra ta empiricka presnost

- splitting and joining buckets
  - we want to keep the number of buckets at $k$, but at some time, some of the buckets beckome too large (we want to keep bucket size $\boh (\frac{n}{k})$
    - so we split some bucket and join another bucket

- epochs and protected thresholds
  - after splitting, we cannot join right away

- if some item occurs multiple times this can cause a problem
  -  if it occurs $n$ times, tak potom ten bucket nemuze mit velikost $\boh(\frac{n}{k})$

## Paper reading

### Definitions

- aspect ratio $\alpha$
  - cim vetsi rozdil mezi min a max prvkem ve streamu, tim vetsi
  - cim mensi rozdil mezi nejblizsimi dvema prvky, tim take vetsi
  - cca asi odpovida tomu, jak moc musime byt presni a pres jakou vzdalenost

- uniform rank error
  - dostaneme parametr presnosti $\alpha$ a vyzadujeme, aby pro libovolnou query $x$ byl $|r'(x) - r(x)| \leq \eps n$
  - pro libovolnou quantile query $q$ vyzadujeme, aby vysledek $q'$ splnoval $|q-q'| \leq \eps$

### Algorithm overview

- we have $k$ buckets

- somehow we accumulate error per each item per time it participates in a split
  - so we try to limit the number of splits each item participates in

- heuristic error
  - tells how much the interpolation error should roughly be (per some bucket)
  - the bigger the rate of change of growth of CDF, the bigger the error should be

- how to decide which buckets to join
  - the CDF needs to have small heuristic error (second derivative there should be small)
  - the bucket size cannot be larger than $\frac{3}{4}$ of max capacity
  - (so the three dots cannot be too far apart there + we want to minimize the "curvature" around that point)

- epochs
  - time intervals between certain amount of inputs are done
  - cannot split a bucket which was created by a split until this epoch is over
