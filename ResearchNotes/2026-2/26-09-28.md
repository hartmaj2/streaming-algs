# Further analysis of KLL in SSBD 4

## Analysis of error for single element

- first we note that each compaction at level $l$ contributes $\in \{-2^l,0,2^l\}$ error
- also, if it produces error, it produces it both ways with equal probability $\rarr$ the error is unbiased (why do we care about this?)

- we would like to bound $\Pr[ |Err| > \eps N]$

- for this it is good to know # of compactions per level which is $\in \boh(2/c)$ (the argument uses # of passed elements up * # of compactions can't exceed capacity of next level)

- then we use this fact, Chernoff-Hoeffding and the fact that $c \in (0.5,1)$ to bound the error to something exponential 

- in the bottom of the ratio in the exponent is $2^{2h}$ which we can bound by and argument on what the highest level $h$ can be (smallest $h$ s.t. $N \leq 2^hk$) ($k$ is cap. of highest level)
  - so we have $h \in \log(N/k) + 1$

- setting a nice $k = \boh(1/\eps \sqrt{\log(1/\eps)})$ makes the error $\boh(\eps)$

## Analysis of error overall

- we use the fact, that for error $\eps N$ it is enough to just be able to accurately answer rank queries at $\eps N, 2\eps N, \ldots, (1-\eps)N$ (in total $1/\eps -1$ points)

- we need to bound the probability, that at least one of these points fails but that is by union bound $\leq \boh(\eps) (1/\eps - 1) \in \boh(1)$
  - i.e. we know that with some nonzero probability, all of the points are accurate enough for rank query

## Space analysis

- since the levels decrease in size exponentially, the size is dominated by the buffer at level $h$ which has capacity $k=\boh(\frac{1}{\eps} \sqrt{\log (1/\eps)})$

- but we cannot forget that there is also a sequence of levels of size $2$ for the smallest buffers so we also have the term with size $\boh(h)$
  - for $h$ we can calculate that $h \in \boh(\log(\eps N))$

## Time analysis

- we will keep the buffers sorted to make the moving of elements up and merging them into higher level faster (just by a simple merge of sorted arrays)
  - it also makes computing the rank faster

### Merging

- the problem is, that we can touch each element multiple times
  - luckily, we can see that in total, only $1/2$ of elemens survive first merge, $1/4$ survives second merge etc. so in total we have only $\boh(N)$ merges which we can charge to the elements and the amortized costs will be good

### Query

- we can just binary search in each of the $h$ buffers

- largest buffer has size $\boh(k) = \boh(\frac{1}{\eps} \sqrt{\log (1/\eps)}))$ and there are $h \in \boh(\log(\eps N))$ buffers in total
  - but we don't have to perform binsearch at each lvl

- observe that $\boh(\log(k)) = \boh(\log(1/\eps))$, so binsearch at each level is bounded by this number
