# Revision of count-min

## Idea of count-min sketch

- goal: compute frequencies of incoming items

- we use multiple, lets say $k$, hash functions into $b$ buckets
  - the functions need to be $c$-universal

- process:
  - when an item $x$ arrives we do:
    - compute for each $i$, $h_i(x)$ and increment the table there
    - i.e. $T_{i,h_i(x)} \larr T_{i,h_i(x)}  + 1$

- query:
  - to answer a query, we select $\min_{i \in [k]} (T_{i,h_i(x)})$

- we would like to claim, that for some $\eps$ and $m$ incoming updates, we have error at most $\eps m$ with reasonable probability $\delta$
  - i.e. if $X_{i,x}$ is the **surplus** value in bucket $T_{i,h_i(x)}$ at the and of the algorithm, we want $\Pr[X_{i,x} \geq \eps m ] \leq \delta$ for some constant $\delta$

- why it works?
  - we can compute $\E[X_{i,x}]$ and then use Markov inequality

- lets use $Y_{x,y}$ as the indicator that $h_i(x) = h_i(y)$

- $X_{i,x} = \sum_{y \in [n] \setminus \{x\}}Y_{x,y} \cdot v_y$

- so $\E[X_{i,x}] = \Pr[h_i(x) = h_i(y)] \cdot \sum_{y \in [n] \setminus \{x\}}v_y \leq \Pr[h_i(x) = h_i(y)] \cdot m \leq \frac{c}{b}m$ 

- then by Markov $\Pr[X_{i,x} \geq  \frac{2c}{b}m] \leq 2^{-1}$
- so the probability, that all the estimates are shitty is $\leq 2^{-k}$ since how we chose the hash functions is independent

- based on error $\eps$ we choose the number of buckets $b$ to be $b \deq \frac{2c}{\eps}$ 

- and for $k$ something like $k \deq \log(\delta^{-1})$

# Count sketch

## Idea and algorithm

- it is almost identical to count-min sketch
- the main difference is, that we also have another set of $k$ hash functions which select sign $s_i \in \{-1,1\}$ for each row $i$
- the meaning of the sign is, that we eighter use the counter in row $i$ in negative direction or in positive direction (this intuitively makes the colliding elements change our buckets in both directions so the estimates will not be biased)

- another difference is now in the procedure, how we extract our answer:
  - first, we multiply our counters back by the sign function $g_i$
  - then we take the median of the resulting $k$ values

- why this works?

## Analysis of Count sketch

- first, we need to define good random variables that we want to bound

- $Y_{i,y}$ ... element $y$ hashes to same bucket as $x$ under $h_i$ (indicator)
- we define $X_{i} \deq v_x + E_{i}$ (so the actual counted value will be defined as the real count + some error (either positive or negative))

- we also know that $X_i = g_i(x)\cdot \sum_{y \in [n]} (Y_{i,y} \cdot v_y \cdot g_i(y))$
  - notice that for $y=x$ we have the sum equal to $v_x$

- now we need $2$-independence of $g_i$ to show that $\E[E_{i,y}] = 0$ for each $y \neq x$
  - thus also $\E[{E_i}]=0$ so our estimate is unbiased

- for the actual bound of the error, we will need to use Chebyshev's inequality so we will need to compute variance of $E_i$
  - we can notice that $\Var(E_i) = \E[E_i^2]$

- since $E_i^2$ is a square of a sum, we basically produce a sum of all ordered pairs
  - we notice, that if $y \neq y'$, then the term in the sum has $\E[g_i(y) \cdot g_i(y')] = 0$ by $2$-independence again

- so we only need to compute the sum of the diagonal terms $\sum_{y \neq x}Y_{i,y}^2 \cdot v_y^2 \cdot g_i(y)^2 \leq \frac{c}{b} \sum_{y \neq x} v_y^2$

- now we use the Chebyshev inequality to show, that the probability that the error is big is small

# Dyadic count sketch

- goal: 
  - answer rank and quantile queries on an ordered universe $\mc{U}$ with $U \deq |\mc{U}|$ in time $\log U$

- idea:
  - we split the universe in $\log U$ levels
  - on level $j$ we have intervals of size $2^j$ and on the highest level, we have intervals of size $U/2$

- we use either Count Sketch or direct counting of occurences on each level
  - we count directly if $U / 2^j \leq \text{summary size of count sketch at lowest level}$

- each level corresponds to some prefix length of the elements from $\mc{U}$

- update:
  - to update, we proceed from bottom to top 
  - at level $j$, we put the prefix $x[:-j]$ to the corresponding bucket

- rank:
  - again from bottom to top
  - we inspect $x[-j]$ and if it is odd, then we add the value in bucket $(x-1)[:-j]$ to $R$
  - return $R$ at the end

- quantile query:
  - this time we go from top to bottom
  - we have value $\phi$ which is the rank for which we want to find the corresponding element
  - we also have $M$ which is the rank accumulated so far
  - at level $j$, let $R$ be the rank accumulated in the left child of the node we're coming from
    - we check if $M + R \leq \phi$ and if yes, we set $M \larr M + R$ and proceed to the right tree
    - otherwise we just proceed to the left tree
