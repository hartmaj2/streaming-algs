# Notes from reading optimal quantiles approximation in streams

## Definitions

- single quantile approximation problem
  - the probability guarantee only needs to hold for any single element I inspect

- all quantile approximation problem
  - the probability guarantee on error must be satisfied by all elements at once

- observation - if I can answer rank queries with precision $\eps n / 2$ of elements spaced out by $\eps n / 2$, then I can answer any rank query with precision $\eps n$

- mergeability - we can create sketches of multiple parts of the stream simultaneously and then combine the sketches together to obtain a single sketch
  - mergeable - exists a merge operation, which when it merges two summaries that ran on streams that together yield the big one give at least as good result as if we had just one summary run on the whole stream

- lower bound for space of any algorithm computing rank
  - if we had alg that could compute rank with $\eps n$ error, than we could take $m = \lf \frac{1}{4 \eps} \rf$
  - then let $b$ be arbitrary sequence of $m$ bits 
  - now we create a stream for our algorithm which consists of numbers $n_i = 2i + b_i$
  - the algorithm determines rank with error $n \eps = m \eps \leq \frac{1}{4} < \frac{1}{2}$ so it determines it precisely
  - now when we want to know value of a certain bit $b_i$, we can just ask a rank query on $R(2i)$ which will be $i$ iff $b_i$ is $0$

## Compactors

- compaction
  - when I have $k$ items and all have weight $w$ I can then select items on even/odd positions and remove them while increasing the weights of the remaining items to $2w$
  - the important thing is, that the result of any query changes by at most $w$

- what is the use of compaction?
  - we will have parameter $k$ which is capacity of a compactor, when we compact $k$ items using this compactor, we need to start a compactor at the level one higher
  - the question is, how many compactors do we need to process $n$ elements, it turns out to be $\log ( n / k)$
  - we use the fact that error is $w_h$ on level $h$
    - also $w_h = 2^{h-1}$
    - now we need to know how many compactions we perform at level
      - we denote it by $m_h$ and we know $m_h \le n / k w_h$ ($k w_h$ is the total weight consumed by one compaction)
    - then we will have error $\sum_{h=1}^{H}w_h * m_h = \sum_{h=1}^H n/k = H n / k \apx \frac{n}{k} \log (n / k)$
    - the space usage is $\apx k  \log(n/k)$

  - important realization:
    - higher k $\rarr$ higher space usage
    - higher k $\rarr$ lower error

  - it turns out that the best value for $k$ is:
    - $k = (1/\eps) \log(\eps n)$

### Improvements

- make capacity of lower compactors exponentially smaller
  - $k_h = k_H (2/3)^{H-h}$
